# spec-r31 标注锚点误判 orphan 修复

## 根因（本次「镜头 4」）

`director/markup._anchor` 只从单调递增的 `search_from` 往后 `content.find(text, search_from)`：

- 镜头 1 的台词 `*` 精确命中了正文里的 Markdown `**诡异食府**`，游标从 1226 跳到 3677；
- 镜头 2 的短台词「生骨汤」又命中了后文对白（3968），游标越过镜头 4 的真实位置（3724）；
- 镜头 4 的 14 行台词其实与正文**逐字一致**，但因位于游标之前，全部被判 `orphan`，
  于是出现「镜头 4 的台词未在正文中找到」。

结论：不是文本差异，是**顺序游标被重复短句/符号带偏**导致的误判。

## 触发条件（按真实可能性）

1. 单调游标 + 重复短句/符号（可修，本次主因）：短台词先匹配到正文靠后的同文，游标越过后续镜头。
2. 标点/引号/空白/省略号/破折号差异（可修）：精确子串匹配，`「」` vs `“”`、`……` vs `...` 都会失败。
3. 模型改写、缩写、扩写台词（不可修）：正文里确实没有这段文字，必须人工改正文或标注。
4. 台词跨段落/多句合并（部分可修）：合并后掺入额外文字则无法匹配。
5. 前置/后置包裹词（如「他低声说：」+ 台词，不可修）：包裹词不在正文中。
6. 正文在标注后被修改（不可修）：旧文本已不存在。

## 修复

`_anchor` 改为三层匹配，并返回 `exact / shifted / orphan`：

1. 游标后精确匹配；
2. 全章同文：优先游标之后最近一处，否则取离游标最近的一处（修正游标漂移）；
3. 标点/空白归一化匹配：正文与台词都只保留文字数字（`_normalize_for_match` / `_normalized_map`），
   用预计算的「归一化字符 → 原文下标」映射回原文位置；归一化串 ≥4 字才启用，避免误命中。

其他约束：

- 归一化长度 <3 的碎片（如 `*`）不推进游标，避免再次带偏；
- 能校正的锚点记 `shifted`（schema 已允许），不产生硬告警，合并为信息级
  「【已自动修正】镜头 N 有 X 行台词锚点按同文就近校正」；
- 归一化后仍找不到才记 `orphan` 并保留「台词未在正文中找到」告警；
- 锚点只是定位信息，行 ID 复用逻辑不变。

## 验证

- 桩：引号/省略号差异 → shifted；`*` 不推进游标；游标漂移后回找较早同文；真缺文仍 orphan 并告警。
- 真实工程副本（`chp_01M78DRDHS6X7PKWGDZ8W4G7A0`，17:20 标注文本）：
  - 修复前：148 行 orphan（镜头 4 有 14 行）；
  - 修复后：0 行 orphan、3 行 shifted、3 条硬告警（均为一品/二品/三品被当成说话人，正文里是菜单名）；
  - 同步回章节：`lines_added=0`、`lines_updated=0`（未改说话人），旧行 ID 与音频引用全部保留。
- `python -m compileall -q src` 通过。
