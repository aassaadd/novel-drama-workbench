# 剩余里程碑路线图（2026-11-09）

> 背景：LLM 联调（oMLX / 写作）暂时搁置，机器上还有其它占内存的任务在跑。
> 本路线图把「不占大显存、现在就能做」与「必须等机器空闲」分开，先推进前者。
>
> 约束：单并发、小批量验证；每次合成报峰值内存；权重与产物不放系统盘；已通过的 schema 语义不改。

## 2. 现在就能做（不占大显存）

### R1 行级批量合成
- 拆解：① 选出过期/失败行（复用 `is_line_stale`）② 解析角色 → 音色变体 → 参考音频 ③ 逐行合成、写回 `line.tts`（asset/duration/provider/variant/chunks）④ 侧车 `<wav>.json` ⑤ 批次报告 `.ndw/tts_batches/<batch_id>.json`（逐行结果、总耗时、峰值内存）。
- 批次控制：`--limit` 限制行数、`--scene` 限定场景、`--batch-size` 分批汇报；**单并发**，失败逐行记录后继续。
- 验收：抽 3~5 行跑通；成功行 `status=ready` 且有实测 `duration_ms`；产物与侧车都存在；失败行不影响后续行；报告含峰值内存与总耗时。

### R2 音色库变体管理
- 拆解：`voices.json` 读写（`voice.schema.json` 校验）；角色 → 多套变体（参考音频、来源、情绪标签、provider 可用性、试听记录）；增删改查；绑定角色；试听一条。
- 验收：新建角色 → 加 2 个变体（1 预设占位 / 1 克隆参考）→ 绑定 → `voice show` 完整 → 试听产物落盘并回写 `preview_asset_id`；删除默认变体被拒绝；克隆变体无授权确认被拒绝。

### R3 时间轴（含静音事件）
- 拆解：台词行按顺序累加（实测时长优先）；导演脚本 `silence_events` 转成 `before/after` 额外停顿；输出可核对时间表（行号、说话人、起止、时长、文本）。
- 验收：建轴成功且 schema 校验通过；时间表与音频实际时长一致（误差 < 50 ms/行）；静音事件体现在相邻行间隔。

### R4 整章语音拼接
- 拆解：读时间轴 → 收集已就绪语音 → `ffmpeg` 以 `adelay + amix + apad` 拼成一个 wav（含静音填充）→ 探测时长、大小、峰值内存。
- 验收：输出时长与时间轴总时长误差 < 100 ms；缺失行以静音填充并在报告列出；不混音效。

### R5 导出
- 拆解：SRT（逐行时间码）+ 时间轴清单（TSV/JSON）。
- 验收：SRT 条目数 = 时间轴语音段数；时间码单调递增；清单含行 ID、说话人、起止、时长。

### R6 导演脚本手动标注与校验
- 拆解：定义行式标注语法（镜头/台词/音效/静音/画面/动画）；规则解析成 `director-script.schema.json` 结构；锚点按正文段落块计算，找不到标 `orphan` 并告警。
- 验收：示例标注能解析并通过 schema 校验；缺字段、非法枚举、`i2v` 无画面等给出明确错误；不调用任何 LLM。

### R7 图像/视频/混流接口 + dry-run
- 拆解：`image/video run --dry-run` 打印将调用的模板与参数并显式标注 `NOT_IMPLEMENTED`；`mux` 只输出计划，`--render` 返回 `NOT_IMPLEMENTED`。
- 验收：三条命令都返回退出码 3（未实现）且不下载权重、不实跑；计划中包含输入、输出、模板与缺失项。

## 3. 必须等机器空闲（图形/视频/大模型）

| 编号 | 为什么必须等 | 依赖 | 首次运行要记录 |
| --- | --- | --- | --- |
| R8 图像 | ComfyUI + 图像权重常驻显存 | R7 接口、R6 脚本画面元素 | 峰值内存、单张耗时、显存占用 |
| R9 视频 | 5 秒视频显存最重 | R8 选中图（i2v） | 峰值内存、单段耗时、失败回退率 |
| R10 混流 | 需要 R8/R9 产物 + 编码 | R4/R5/R7 | 编码内存、音画同步误差 |
| R11 LLM 联调 | oMLX 服务占 29.48 GB 上限 | 设置库/章节数据 | 首 token、整章耗时、内存峰值 |

原则：先保证「无模型链路」全部可验收；等机器空闲后按 R8 → R9 → R10 → R11 串行推进，每项跑通再开下一项。

## 4. 依赖顺序

```
R0/R0b（已完成）
   ├─ R1 批量合成 ──→ R3 时间轴 ──→ R4 拼接 ──→ R5 导出
   ├─ R2 音色库（供 R1 取参考音频）
   ├─ R6 导演脚本（规则） ──→ R3（静音事件）
   └─ R7 接口/dry-run ──→ R8 图像 ──→ R9 视频 ──→ R10 混流
                                              R11 LLM（暂停）
```

- 串行：R1 独占 TTS 模型；R8/R9/R10/R11 各自独占重资源。
- 并行：R2、R3、R4、R5、R6、R7 都只吃 CPU/磁盘，可在 R1 的批次之间穿插。
- 上游：R2 → R1（音色参考）；R1 → R3（实测时长）；R3 → R4/R5；R6 → R3（静音事件）。

## 5. 验收与回报节奏

1. 路线图（本文）—— 已出。
2. R1 批量合成跑通 —— 报整章音频路径、总耗时、峰值内存、成功/失败行数。
3. R2 音色库 —— 报变体数与试听产物路径。
4. R3 时间轴 —— 报总时长、行数、静音事件数、时间表路径。
5. R4 拼接 —— 报输出路径、时长误差、峰值内存。
6. R5 导出 —— 报 SRT 与清单路径、条目数。
7. R6/R7 —— 报解析结果与 dry-run 退出码。

## 6. 风险与红线

- 不改 `schema/*.json` 的既有语义；新增数据只进 `.ndw/` 或派生文件。
- 权重、参考音频、产物不落系统盘；测试工程放 `/Volumes/other`。
- 所有合成单并发；批次失败不中断，但必须在报告里逐行可见。
- 图像/视频/混流本轮只留接口，不下权重、不实跑。
