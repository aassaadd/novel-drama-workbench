# 上下文上限与输出口径（专项说明）

## 目标

不再对输出侧设置任何人为上限，只保留输入侧上下文限制，并把「要写多少字」交给提示词里的目标字数与每轮节拍数决定。

- 页面入口：设置 → 正文生成（可改两项）/ 上下文与输出（只读）
- 接口：`GET`（现状 + 可改项）、`POST /api/ui/config/generation`（只写每轮节拍数与最大轮数）
- 解析模块：[budgets.py](../src/novel_drama/writing/budgets.py)（只剩输入侧上下文预算）
- 请求落点：[writing.py](../src/novel_drama/adapters/writing.py) 的 `_build_payload`

## 正文生成可改项（恢复的保存接口）

| 设置项 | 键 | 取值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| 每轮节拍数 | `writing.multi_turn.beats_per_round` | `0` 或 `1–50` | `0`（自动分配） | `0` 表示按本章节拍总数自动均分轮次 |
| 最大轮数（保险） | `writing.multi_turn.max_rounds` | `1–20` | `8` | 防止跑飞的轮数上限 |

- `POST /api/ui/config/generation` 请求体：`{"values": {"writing.multi_turn.beats_per_round": 3, "writing.multi_turn.max_rounds": 6}}`。
- `null` / 空串表示删除覆盖层里的键，回落到 `config.yaml` 或内置默认。
- 白名单之外的点分键（尤其 `omlx.max_tokens` 等输出预算相关项）一律 400：「不支持修改」；非整数、越界也 400。
- 写入沿用覆盖层机制（`save_ui_config` / `remove_ui_config`），保存即生效，不需要重启。
- 返回结构 = `GET` 的现状 + `saved_to`，设置页据此刷新值、默认值与来源。

## 设置页与生成弹窗的联动

- 设置页「正文生成」分组：自动分配勾选框 + 每轮节拍数输入、最大轮数输入；每项显示当前生效值、默认值与来源。
- 来源只给用户可读说法：**在设置页改过 / 使用默认配置 / 出厂默认**；配置键不占正文位置，只在悬浮提示里出现（如「配置项：writing.multi_turn.max_rounds」）。
- 输入即时校验并禁用保存；保存中按钮文案「正在保存…」，恢复默认「正在恢复…」。
- 单章与整幕弹窗共用同一套默认参数行与跳转实现：
  - 单章：每轮节拍数、最大轮数（输入框下方）与温度、思考开关（底部默认参数区）均可点；
  - 整幕：每轮节拍数、最大轮数、温度、思考开关均可点；顶部文案不再写「来源已标注」，改为「点带虚线下划线的行可去设置页调整」。
- 点击后跳到 `#/settings?section=…&focus=…`，设置页滚动到对应分区并聚焦、高亮该控件。
- 跳转前把恢复信息写入 `sessionStorage`（单章：模式 / 节拍数 / 最大轮数 / 分轮开关；整幕：幕 ID / 幕序号 / 已选模式）与焦点项；
  返回小说页后重新读取默认值与来源，并恢复对应弹窗：单章回到本章，整幕回到原幕，已选模式与已填参数保留。
  设置页顶部显示「返回生成」，按钮与 Esc 都回到原弹窗；暂存 10 分钟过期。

## 已删除的设置项与概念

以下内容整体删除，不再出现在设置页、覆盖层或请求推导里：

| 已删除 | 说明 |
| --- | --- |
| 正文每轮输出预算 | 原先按字数推导，作为每轮 `max_tokens` 截断依据 |
| 单轮正文预算 | 不分轮整章请求的输出预算 |
| 推导用每章节拍数 / 默认每章预期字数（作为预算输入） | 「每章预期字数」仍保留为写作目标，不再参与输出预算 |
| 思考预留分档（2048 / 4096） | 不再为思考额外预留输出 token |
| 章节摘要预算（5171） | 摘要请求不再带固定 `max_tokens` |
| 工具调用基础预算 / 单项预算 / 单次估算上限（4096 / 16384 等） | 大纲、角色、世界、标注等工具调用不再估算输出预算 |
| 全局最大输出（`omlx.max_tokens`） | 不再作为设置项，也不再写入请求 |
| 四阶段思考（正文 / 摘要 / 审校 / 抽取） | 只保留一个全局思考开关（以及开启时的强度） |

页面上与输出预算相关的公式、来源标注、保存与恢复默认交互一并移除；恢复的保存接口只接受上面两项，不能再把预算项加回来。

## 请求里的 `max_tokens` 怎么传

适配器在 `_build_payload` 里统一计算：

1. 取上下文上限：`min(检测到的窗口, omlx.context_window)`，都没有则视为未知。
2. 估算提示词：所有 messages 的字符数之和 + 256 固定开销（中文按 1 字 ≈ 1 token）。
3. 有上限时：`max_tokens = 上下文上限 − 提示词估算`，**不额外留人为余量**；模型自己输出结束符停止。
4. 上下文未知时：请求体不带 `max_tokens`，由模型自身决定何时停止。
5. 提示词估算已达到或超过上限时：直接抛出中文 `AdapterError(INVALID_INPUT)`，说明输入约占多少、窗口多少，提示缩短输入，不做静默截断。

`TextGenRequest` 上的 `max_tokens` 字段已删除；音效/BGM 改写与音色描述等短任务也不再传固定值。

## 输入侧上下文上限怎么生效

- 配置项：`omlx.context_window`，由「测试连通」按服务端返回值回填，也可手填。
- 装配预算：`context_budget_tokens(config)` 优先用该窗口；未知时用 32768 兜底（仅输入侧，不是输出预算）。
- 使用位置：
  - `writing/service.py`：章节上下文装配；
  - `writing/continuation.py`：断点续写装配；
  - `writing/editing.py`：整章润色/改写装配。
- 超限行为：装配器按既有顺序裁剪可裁剪内容（前文摘录 → 最近章摘要 → 全书前情摘要 → 世界细节 → 角色卡细节）；故事圣经与任务指令不可裁剪，仍放不下时抛出明确中文错误，不静默截断。

## 思考

- 全局总开关 `omlx.enable_thinking`（最高优先级）：关闭时所有调用点都不思考。
- 开启时按调用点三态决定：**系统自动 / 开 / 关**；「系统自动」= 没有覆盖项，回落到 [thinking.py](../src/novel_drama/writing/thinking.py) 的内置清单。
- 内置清单默认开启：世界设定、故事圣经、幕大纲、章节清单、节拍拆分、角色设定、一致性审校。
  默认关闭：正文分轮/单轮、续写、补写、压缩、重写、章节摘要与滚动摘要、正文反推大纲、角色状态回流、脚本标注、音色描述、音效/配乐提示词。
- 优先级：全局关闭 > 调用点显式值 > 阶段覆盖 > 系统自动清单。
- 强度 `omlx.reasoning_effort`（low / medium / high）统一跟随全局，不按阶段分档。
- 请求带 `chat_template_kwargs.enable_thinking`；开启时另带 `reasoning_effort`。每次请求记录日志：
  `思考生效 task=… stage=… enabled=… source=global-off|call|stage|auto effort=…`。
- 设置接口：`GET/POST /api/ui/config/thinking`，只写 `writing.thinking.stages.<stage>`，`null` 恢复系统自动。
- 未接入模型调用的项（黄金三章体检、说话人归属、章节标题/简介卖点）当前是规则实现，没有对应 LLM 请求，因此不在清单里。

## 异常保护（不静默）

| 情况 | 表现 |
| --- | --- |
| `finish_reason=length` | 记录 warning，并通过任务进度/通知提示「输出侧未设置人为上限，说明触发的是模型自身输出上限或上游异常，结尾可能不完整」；内容保留，需人工检查重试 |
| 单轮输出明显超出预期 | 本轮实际字数 > max(预期 × 1.5, 预期 + 300) 时提示，说明疑似复述、跑题或模型未自然停止 |
| 疑似复述 | 新一轮开头与已写正文高度重复、去重后新增不足 60% 时提示，并说明已自动去重 |
| 输入占满上下文窗口 | 适配器直接抛中文错误，指出提示词估算与窗口值 |

设置页「上下文与输出」卡片展示：上下文窗口、输入装配上限、最近一次提示词占用（含占比）、最近一次请求的 `max_tokens`（标注为上下文剩余空间）、输出人工上限=无、最近一次结束原因。

## 「保险丝 vs 目标字数」的分工

- 目标字数：写在提示词里的「本章预期字数 / 每轮节拍数」，只影响内容长度要求。
- 保险丝：不再是某个固定 token 数，而是模型自身的输出上限与上下文窗口；请求里的 `max_tokens` 只是把剩余窗口如实交给服务端。
- 因此不要再把按字数推导的值当作截断依据；`finish_reason=length` 出现即视为异常，而不是正常的「写够了」。

## 离线验证

`tests/test_generation_budget.py`：

- 上下文预算优先用窗口、未知时 32768 兜底；
- 请求 `max_tokens` = 窗口 − 提示词估算，且不受旧 `omlx.max_tokens` 影响；
- 窗口未知时不传 `max_tokens`；
- 提示词占满窗口时抛中文错误；
- 设置接口不再暴露输出预算项，保存接口只接受每轮节拍数与最大轮数（预算键 400）；
- 保存 / 恢复默认写入覆盖层并立即反映到 GET 与生成弹窗；
- 思考按调用点三态（系统自动 / 开 / 关），全局关闭时全部不思考；
- `finish_reason=length` 产生异常提示且不触发内容重试。
