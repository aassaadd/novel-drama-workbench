# spec-r26 重新切分场景 / 台词（影响清单 + 人工修改保护）

## 目标

章节页与导演标注页提供明确的「重新切分场景」「重新切分台词」入口。重切前先给出影响清单，
确认后才执行；人工改过的说话人、台词文本默认保留，不静默覆盖；已有音频与媒体文件不删除。

## 交互

- 章节页「拆分」工具组：
  - 未切分：按钮显示「切分场景」「切分台词」；
  - 已切分：按钮显示「重新切分场景」「重新切分台词」，章节信息区显示
    「已切分 N 个场景 / M 行（重切会覆盖）」。
- 标注页新增「重新切分」工具组，同样两个按钮。
- 两页都有「保留人工修改」复选框，**默认勾选**（安全侧）。
- 点击按钮：先请求影响清单 → `window.confirm` 展示清单与当前选择 → 确认后带 `--force` 执行。
  首次切分（尚无场景/台词）跳过确认，直接执行。
- 场景重切成功后提示「记得重新切分台词并重新生成标注」；台词重切提示行数与未识别数。

## 影响清单内容

复用 dry-run 同源的规则函数（`split_scenes` / `split_lines`），不另起估算：

- 已有场景数 / 台词行数 / 已有配音行数 / 人工或标注改动行数；
- 规则将切出的场景数或台词行数；
- 保留模式下可沿用的场景数与台词行数（含配音）；
- 会丢失的台词行、其中人工改动行、已有配音行；
- 是否已有导演标注及镜头数；
- 明细点名（最多 10 条）：场景序号、原因、台词前 40 字。

「人工修改」判定：与规则切分结果相比，台词文本不同（改写/新增）或同一文本的说话人不同。

## 保留策略

- 场景重切 `--keep-lines`：新场景正文与旧场景 `source_text` 完全一致时，整块沿用旧场景
  （场景 ID、台词 ID、配音与图片/视频引用全部保留）；正文变化的场景重建为空场景。
- 台词重切 `--keep-manual`：同文本旧行原样复用（保留 id/情绪/语速/配音）；
  规则结果里没有的旧行（人工改写/新增）按原索引位置插回，最后统一重排 index。
- 两种保留都是显式参数；CLI 默认关闭（保持旧行为），页面默认开启。

## 依赖提示

- 场景重切后必须重新切分台词（新场景没有台词行），并使导演标注失效；
- 台词重切不影响场景划分，但会使标注锚点失效；
- 已有音频/图片/视频文件不会删除，只是相关引用可能失效，需要重新生成。

## 接口与参数

| 入口 | 说明 |
| --- | --- |
| `ndw scene split --impact [--keep-lines] [--max-chars]` | 只读影响清单（JSON + 中文文案），不写盘 |
| `ndw scene split --force [--keep-lines]` | 覆盖重切场景 |
| `ndw line split --impact [--keep-manual] [--scene]` | 只读影响清单 |
| `ndw line split --force [--keep-manual] [--scene]` | 覆盖重切台词 |
| `POST /api/ui/scene/split/impact` | body：`path/chapter/keep_lines` |
| `POST /api/ui/line/split/impact` | body：`path/chapter/keep_manual` |
| `POST /api/ui/scene/split` | 新增 `keep_lines`；原有 `force` |
| `POST /api/ui/line/split` | 新增 `keep_manual`；原有 `force` |

Web 接口继续起 CLI 子进程（与页面、终端完全同一条实现）。

## 不改动

- 不改任何 schema；不修改 `text/splitter.py` 的切分规则；
- 不删除任何音频/媒体文件，不新增一级导航。
