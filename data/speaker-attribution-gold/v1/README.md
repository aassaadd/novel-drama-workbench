# 对白说话人归属金标集 v1

用于评估「切分出的台词行由谁来说」这一步的规则或模型。数据集固定、口径固定，可长期横向比较。

- 语料：真实工程 `tt1`（`/Volumes/other/ndw_runs/tt1`），10 个有正文的章节
- 规模：426 行引号片段，其中 401 行直接对白、25 行非对白引号对照
- 标注方式：逐行人工判定，每条都记录判定依据
- 生效版本：`v1`，2026-11-15 冻结。新增样本请另建 `v2/`，不要改动本目录

## 3. 抽样方法

### 3.1 候选池

1. 取 10 个有正文的章节，按 `\n` 切段，保留段落下标（含空行下标）。
2. 用正则 `“([^”]+)”` 抽取引号片段，共 1122 个。
3. 排除 191 个明显不是当场台词的引号（释义强调、牌匾/纸条/铭文、比喻举例、拟声、转述他人旧话），得到 931 个候选对白片段。

排除规则不是简单的「短句就丢」，而是看上下文是否在引用词语或文字。例如「是“站”，站的方式不对」属于释义，不算对白；「司仪说“一拜天地”」属于转述，也不算直接台词。

### 3.2 分层

候选池按以下 7 类打标签（按优先级从高到低，单标签）：

| 分层 | 判定方式 | 候选池数量 |
| --- | --- | --- |
| `extra_cue` | 上下文出现司仪、村民、大学生、女人等龙套说话 cue | 31 |
| `nested_truncated` | 引号内再有引号，或引号内以逗号/破折号截断 | 66 |
| `cue_mid` | 两个引号之间插入了「X 说，」 | 83 |
| `cue_post` | 引号后紧跟「X 说/道/问/喊」 | 256 |
| `cue_pre` | 引号前紧跟「X 说：」 | 56 |
| `alternation` | 段内多引号或整段只有引号，没有点名 | 294 |
| `bare` | 无直接 cue，靠邻近叙述判定 | 145 |

另设 `multi_candidate`：第 8 章后半与第 10 章同场有 3 人以上，且本句没有紧邻点名，共抽出 35 条。

### 3.3 配额与随机性

- 随机种子：`20261115`
- 配额：`cue_post` 80、`cue_mid` 40、`cue_pre` 45、`nested_truncated` 60、`extra_cue` 30、`alternation` 65、`bare` 45、`multi_candidate` 35，合计 400
- 章节下限：第 3 章 12、第 4 章 10、第 5 章 8、第 7 章 12。不足时从这些章节的裸行/交替行补，替换第 6 章的 `cue_post` 行，避免退化文本和短章被比例抽样挤掉
- 最终又补入 16 条非对白引号对照，以及 10 条多人同场、无任何 cue 的短句，因此总数为 426

分层配额是候选池的抽样配额；人工复核后会按实际判定依据重新归类，所以第 3.4 节的实际分布与配额不同，例如很多「多人同场」行其实带有明确点名，会被改判为 `cue_post` / `cue_pre`，而原本落在其他层、确实无 cue 的短句会被改判为 `multi_candidate`。

抽样脚本未入库。重抽时按本节规则实现即可；金标一旦冻结不需要重抽。如需复现同一批 400 条基础样本，必须使用同一个种子、同一个候选池和上述章节下限逻辑。

## 4. 标注口径

### 4.1 gold 取值

- `chr_*`：角色卡内角色，表示**这一行由该角色说出**
- `extra:名称`：角色卡外的龙套，如 `extra:司仪`、`extra:无脸面具`
- `unknown`：无法确定说话人，或这一行根本不是对白

三类分开统计，不要混为一谈：

- 「卡内角色」用于算非未知行准确率
- 「龙套」是独立类别，模型应输出 `extra:名称`；如果模型只允许输出卡内角色，可用 `--extra-as-unknown` 把龙套行折算成 unknown 再算
- 「unknown」包含两种子类：`kind=dialogue` 的真正无法判定（3 条），`kind=non_dialogue` 的非对白引号（25 条）

### 4.2 判定规则

按以下优先级判定：

1. **引号后紧跟点名**：以后置点名为准。
2. **引号前有点名或明确动作主语**：以前置点名为准。例如「周也把地图摊在桌上。“这是……？”」归周也。
3. **引号中间插入 cue**：「“对，”周也说，“是总枢纽。”」两句都归周也，依据记为 `mid_cue`。
4. **只有代词**：「他说」「她问」「纸人说」「女人说」归最近且唯一的先行词；若先行词有歧义，降为 `turn` 或 `unknown`。
5. **无点名短问答**：只有两人在场且严格一问一答时，按轮次交替推断，依据记为 `turn`。
6. **多人同场且无点名**：不强行猜，无法唯一确定时标 `unknown`。
7. **称呼不等于说话人**：「周也，你听」是九斤说的，「九斤」只是称呼。说话人看引号外的叙述主语，不看引号内的称呼。
8. **旁白、心理活动、内心独白**不入集；数据集只覆盖引号内的直接台词。
9. **引号内再有引号**：只给外层台词标一个说话人；内层引号是台词内容的一部分，不单独成行。
10. **半句被截断**：按能判定的句首说话人标注，`line_text` 保留原始截断文本，不做补全。

### 4.3 无法判定与对照组的处理

`tt1` 正文 cue 密度很高，绝大多数台词都有点名、代词或严格交替可依。真正无法判定的对白只有 3 条：

- 第 5 章「周也。」：正文写「九斤听见周也在叫自己的名字」，叙述与引号内容冲突
- 第 9 章「再往前。」：黑暗中的神秘声音，身份未揭示
- 第 10 章「各位祭品。」：祭坛下方传来的声音，正文未点名

3 条不足以让 unknown 指标有统计意义，因此另抽 25 条非对白引号做对照（`kind=non_dialogue`，`gold=unknown`）。这类行如果被上游当作台词，正确行为是拒绝归属，而不是硬猜一个角色。两项合计 28 条 unknown，占 6.6%。

计算 unknown 指标时，报告里应同时给出 `kind=dialogue` 与 `kind=non_dialogue` 的拆分，避免把「拒绝非对白」误读成「识别不出说话人」。

## 5. 数据格式

`gold.jsonl` 每行一个 JSON：

```json
{
  "id": "tg-v1-0001",
  "source_uid": "c01-p004-q0",
  "source": {
    "project": "tt1",
    "work_id": "wrk_01M7C190165A9EBJ4GWN5SHHD0",
    "chapter_index": 1,
    "chapter_title": "红盖头",
    "paragraph_index": 4,
    "quote_index": 0
  },
  "line_text": "我早知道了。",
  "paragraph_text": "“我早知道了。”九斤说。她其实不知道，……",
  "prev_paragraph": "",
  "next_paragraph": "",
  "gold_speaker": "chr_linjiujin",
  "gold_name": "林九斤",
  "kind": "dialogue",
  "evidence": "post_name",
  "stratum": "cue_post",
  "note": "引号后‘九斤说’"
}
```

字段说明：

- `id`：数据集内稳定主键，按章节、段落、引号顺序编号
- `source_uid`：`c{章节}-p{段落下标}-q{段内引号下标}`，方便回原文核对
- `paragraph_index` 是 `content.split("\n")` 的下标，包含空行，与生产切分口径一致
- `line_text`：引号内文本，不含引号
- `paragraph_text` / `prev_paragraph` / `next_paragraph`：判定所需的上下文，便于脱离原工程复核
- `kind`：`dialogue` 或 `non_dialogue`
- `note`：补充说明；单一 cue 行可省略，歧义行、冲突行、非对白行会写明原因

## 6. 指标定义

`score.py` 输出四项核心指标：

1. **非未知行准确率**：只在 `gold_speaker` 为卡内角色的行上计算。`correct / card_total`。这是最能反映「正常台词有没有说对人」的指标。
2. **整体准确率**：全部 426 行上精确匹配。龙套必须输出 `extra:名称`；使用 `--extra-as-unknown` 时，龙套行预测为 `unknown` 也算对。
3. **unknown 精确率**：`(预测 unknown 且金标 unknown) / 预测 unknown 总数`。衡量「拒绝归属」是否可信；分母为 0 时输出 n/a。
4. **unknown 预测数**：模型一共预测了多少行 unknown。它和精确率一起看，防止模型只敢在极少数行上输出 unknown 刷高精确率。

附带输出：覆盖率、缺失/非法条数、unknown 召回率、龙套行准确率，以及按困难类型、按依据类型的准确率。

预测对齐规则：

- 预测行用 `id` 或 `source_uid` 对齐金标；两者都没有的行会被忽略并计入「无法对齐」
- 说话人字段可用 `speaker` / `speaker_id` / `pred` / `prediction`
- 值可以是角色 ID、姓名、别名、`extra:名称`、`unknown`
- `null`、空串、`chr_unknown`、`无法判定` 都按 `unknown` 处理
- 完全没有该条预测记录才计「缺失」；记录在但说话人字段为 `null` 计为 unknown
- 角色卡外的姓名自动归一为 `extra:原名`；与金标龙套名不一致即判错，不会静默算成卡内角色

## 7. 使用示例

预测文件 `pred.jsonl`：

```json
{"id": "tg-v1-0001", "speaker": "周也"}
{"id": "tg-v1-0002", "speaker": "chr_linjiujin"}
{"id": "tg-v1-0003", "speaker": "unknown"}
```

运行：

```bash
python score.py --gold gold.jsonl --pred pred.jsonl
python score.py --gold gold.jsonl --pred pred.jsonl --extra-as-unknown
python score.py --gold gold.jsonl --pred pred.jsonl --json
```

只输出卡内角色、把龙套统一输出 unknown 的模型，应加 `--extra-as-unknown`；这样整体准确率才与它的能力边界匹配。两组数字都要报告时，分别跑一次即可。

机器可读结果里包含 `per_stratum` 与 `per_evidence`，可用于定位难点，例如 `cue_mid` 和 `nested_truncated` 的准确率是否显著低于 `cue_post`。

## 8. 已知局限

1. 语料只覆盖 `tt1` 的 10 个有正文章节，不含无正文的章节，也不含其他工程；跨工程泛化需另建评测集。
2. 第 3、5 章正文明显退化、重复，句法不完整；这两章只进少量样本，用于覆盖「文本损坏时的判定」，不代表整体分布。
3. 真正无法判定的对白仅 3 条，unknown 指标主要靠 25 条非对白对照支撑；不要把该指标解读为「模型识别模糊说话人的能力」。
4. 只标单说话人。多人齐声、群像喊话按句首可判定的主说话人处理，未单独建模。
5. 数据来自真实工程，包含原文的错别字、重复句和断裂句，未做清洗；这是刻意保留的。

## 9. 维护约定

- 本目录冻结，不修改已有行。发现标注错误时，在 `v2/` 中修正并在变更说明里列出 `id` 与原因。
- 新增语料或新增困难类型时，先更新本文档的分层与配额，再抽新样本。
- 任何口径变化（例如把龙套并入 unknown）都必须升版本，否则历史数字不可比。
